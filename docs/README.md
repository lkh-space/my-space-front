# 프로젝트 문서화 (Documentation)

이 디렉토리는 **My Space Frontend (`my-space-frontend`)** 프로젝트의 프론트엔드 아키텍처 의사결정, 비즈니스 기능 규격, UI 컴포넌트 동작 및 백엔드 API 클라이언트 연동 사양을 체계적으로 기록하고 관리하는 공간입니다.

본 프로젝트는 코드 작성에 앞서 명세를 먼저 정의하고 검증하는 **스펙 주도 개발(SDD, Spec-Driven Development)** 프로세스를 엄격히 준수합니다.

---

## 디렉토리 구조 (Structure)

| 경로 | 용도 | 표준 포맷 | 설명 |
| :--- | :--- | :--- | :--- |
| [`adr/`](./adr/) | 아키텍처 의사결정 기록 | [MADR 4.0.0](https://adr.github.io/madr/) | 전역 상태 관리, 번들러, 라우팅 전략, 공통 모듈화 등 구조적이고 번복하기 어려운 기술적 합의 기록 |
| [`specs/`](./specs/) | 기능 및 화면/UI 요구사항 명세 | 프론트엔드 SDD 사양서 양식 | 사용자 관점의 유스케이스, 화면 컴포넌트 인터랙션, 클라이언트 상태 흐름 및 API 연동 규격 명세 |

## 문서화 규칙 (Conventions)

1. **언어 (Language)**:
   - 모든 문서는 **한국어(한글)** 작성을 원칙으로 합니다. 불필요한 한영 병기나 복잡한 외래어 표기는 지양합니다.
2. **파일명 (File naming)**:
   - 모든 문서는 소문자 하이픈 조합의 `kebab-case.md` 형식으로 명명합니다.
   - 아키텍처 의사결정 기록(ADR)은 4자리 순차 번호 접두사를 부여합니다 (예: `0001-vite-react-bundler.md`).
3. **필수 프론트매터 (Front-matter)**:
   - 모든 문서(ADR 및 Spec)는 최상단에 YAML 프론트매터를 선언하여 현재 문서의 진행 및 검토 상태(`status`)를 명확히 관리합니다.
4. **UI 디자인 기준과의 관계**:
   - UI 디자인 및 스타일링(색상, 타이포그래피, 여백, 컴포넌트 규격 등)의 단일 진실 공급원(SSOT)은 프로젝트 루트의 `DESIGN.md`입니다.
   - Specification에서는 `DESIGN.md`에 정의된 디자인 토큰과 UI 패턴을 준수하여 화면 인터랙션 흐름을 기술합니다.
