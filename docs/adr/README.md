# 아키텍처 의사결정 기록 (Architecture Decision Records, ADR)

이 디렉토리는 프론트엔드 모노레포 구조, 주요 라이브러리 선정, 상태 관리 전략, 라우팅 및 빌드/배포 파이프라인 등 핵심 아키텍처 결정 사항을 기록하고 보존하는 곳입니다.

본 프로젝트는 마크다운 아키텍처 문서 표준인 [MADR 4.0.0](https://adr.github.io/madr/)을 준수합니다.

---

## ADR 작성 기준

다음 항목 중 하나 이상에 해당되는 경우 의사결정 기록(ADR)을 작성합니다:

1. **구조적/아키텍처적 영향**: 전역 상태 관리 도입, 라우팅 전략 변경, 공통 패키지 분리, 번들러 및 태스크 러너 전환 등.
2. **번복하기 어려운 결정**: 코드 구현 후 롤백하거나 아키텍처를 뒤엎기에 큰 공수가 동반되는 결정.
3. **핵심 도구 및 라이브러리 선정**: UI 프레임워크/라이브러리(도입 시), HTTP 클라이언트 라이브러리, 데이터 페칭/캐싱 도구(TanStack Query 등) 등 주요 의존성 도입.
4. **지식 보존**: 결정의 배경 맥락과 트레이드오프를 투명하게 기록하여 미래의 유지보수성을 극대화하고자 할 때.

---

## 새 ADR 작성 방법

1. 이 디렉토리에 있는 [`template.md`](./template.md) 양식을 복사하여 `NNNN-짧은-제목.md` 파일명으로 생성합니다. (`NNNN`은 `0001`과 같이 순차적으로 부여되는 4자리 제로패딩 번호입니다.)
2. 프론트매터(Front-matter)와 가이드 섹션의 내용을 프로젝트 맥락에 맞춰 기재합니다.
3. 결정이 확정되고 코드에 적용되면 상태를 **accepted**로 활성화합니다.
4. 이미 내린 결정을 번복하거나 수정할 때는 기존 ADR을 직접 덮어쓰지 않고 **새 번호로 신규 ADR을 작성**한 뒤 기존 ADR의 status를 `superseded by ADR-NNNN`으로 갱신합니다.
